# n8n workflow inventory

n8n is the **workflow orchestration layer**. It runs locally (`docker compose`, service `n8n`, bound to 127.0.0.1:5678) and only starts when `AUTOMATION_WEBHOOK_BASE` is set in `.env`. Every workflow is thin: n8n supplies the schedule or webhook trigger and the hand-off, while the **backend makes every decision** (`backend/app/api/routes/automation.py`). n8n does not do computer vision, access control or door decisions.

## How the pieces fit

1. A trigger fires (schedule or webhook from the backend).
2. n8n calls a backend automation endpoint, which evaluates the rule against the database and returns findings.
3. n8n splits the findings and posts each one to `/api/automation/notify` (in-portal notifications, e-mail when configured).
4. n8n records the run at `/api/automation/runs`, so the portal shows when each workflow last ran and what it found.

Requests carry the automation key from the n8n environment (`AUTOMATION_API_KEY`, set in `.env`); no credential is stored in the exported JSON.

## Files

| Path | Purpose |
|---|---|
| `automation/n8n/json/*.json` | The 23 workflow exports (import into n8n: Workflows → Import from file) |
| `automation/n8n/gen.py`, `build_json.mjs`, `src/` | Generators that produce the JSON from one definition |
| `automation/n8n/export_workflows.py` | Exports the live workflows back to JSON (read-only against n8n) |
| `automation/n8n/test-automation.ps1`, `test_automation.bat` | Calls the backend endpoints the workflows use |
